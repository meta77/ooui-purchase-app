# テスト駆動リファクタリングのためのコード分析・分類

本ドキュメントは、テスト駆動リファクタリング（TDD）の準備として、既存のコードベース全体を読み込み、純粋関数と副作用を持つ操作を明確に分離するための分析結果をまとめたものです。

## 1. 純粋関数の候補
外部の状態（DB・ネットワーク・ファイル・UI状態・グローバル変数）に依存せず、同じ入力に対して常に同じ出力を返す操作です。これらはユニットテストが最も容易です。

*   **`formatPrice(value)`** (`src/store/mockData.js`)
    *   【分類】純粋
    *   【説明】数値を日本円形式の文字列に変換する処理。引数のみに依存しています。

*   **合計金額の算出ロジック** (`PurchaseCreate.vue` の `totalAmount` など)
    *   【分類】混在（要分離）
    *   【説明】現在は Vue の `computed` 内でグローバルな `products` とローカルな `selectedItems` に依存しています。引数として `(items, products)` を受け取り、合計金額を返す純粋な計算関数として抽出可能です。

*   **売上原価 (COGS) の計算ロジック** (`src/store/mockData.js` の `getReportDetails` 内)
    *   【分類】混在（要分離）
    *   【説明】現在はデータの取得（副作用）と計算が混ざっています。「前期末棚卸高」「当期仕入高」「当期末棚卸高」を引数として受け取り、COGSを計算して返す純粋関数として抽出可能です。

## 2. 副作用を持つ操作
ネットワーク通信、状態（ローカルストレージやグローバルな変数）の変更、画面遷移、非決定的な値の取得を行う操作です。

*   **グローバル状態の更新** (`src/store/mockData.js` の `addPurchase`, `addProduct`)
    *   【分類】副作用あり
    *   【説明】`reactive` な配列 (`purchases`, `purchaseItems`, `products`) を変更しています。また、内部で新しい ID を採番する処理（現在の状態に依存する非決定的なロジック）が含まれています。

*   **グローバル状態へのアクセス（Read）** (`src/store/mockData.js` の `getPurchaseDetails` 等)
    *   【分類】副作用あり（外部状態依存）
    *   【説明】引数から結果を計算していますが、グローバル変数（`products`, `purchases` 等）を読み取っているため純粋関数ではありません。

*   **画面遷移** (`PurchaseCreate.vue` などの `save` メソッド内の `router.push`)
    *   【分類】副作用あり
    *   【説明】保存処理の完了後に行われるルーターの操作であり、UI の状態を変更する明らかな副作用です。

*   **現在時刻の取得** (`PurchaseCreate.vue` の `const today = new Date()....`)
    *   【分類】副作用あり
    *   【説明】システム時刻に依存する非決定的な操作です。

## 3. 現在の問題点と分離方針

### 問題点：純粋ロジックと副作用の混在
現在のコードベースでは、ビジネスロジック（売上原価の計算、合計金額の集計、IDの採番など）が、データアクセス層（`mockData.js`のグローバル状態の読み書き）や UI コンポーネント（Vue コンポーネント）の中に直接記述されています。
これにより、計算ロジックだけをテストしたい場合でも、Vue コンポーネントをマウントしたり、モックデータを初期化したりする必要が生じ、テストが困難・複雑になっています。

### 分離方針（リファクタリング計画）
1.  **純粋関数のモジュール化**: `src/utils/` などのディレクトリを作成し、金額計算（合計、COGSなど）やデータのフォーマットを行う純粋関数を移動します。
2.  **ID 採番ロジックの分離**: ID 採番も「既存のIDリスト」を引数に受け取り「新しいID文字列」を返す純粋関数として抽出します。
3.  **依存性の注入 (Dependency Injection)**: コンポーネント内で直接 `mockData.js` の関数を呼ぶのではなく、データのロードと保存のアクションをコンポーネントの外部または Pinia などの Store に寄せ、コンポーネントは計算用の純粋関数を利用して表示状態を作るようにします。

以上により、ビジネスロジックは純粋関数として副作用なく独立してテスト可能になります。
